A Modern LuaLaTeX Kit for Computational Linguistics

Six files. One narrative tutorial. Written in 2026 for a student who just inherited a decade of stale advice from the internet.

Most LuaLaTeX material online was written between 2010 and 2015. Package names drift, defaults change, and a newcomer following those tutorials will spend the first evening fighting inputenc errors instead of writing linguistics. This kit is a small, opinionated starting point for anyone — in particular, students of computational linguistics working with Romance languages (French, Spanish, Italian, Portuguese, Romanian) and IPA.

Everything here assumes a current TeX Live installation and LuaLaTeX as the engine. The six source files below mirror six jobs: understand the engine, keep a reference, start a document, and borrow from three worked examples (Romance languages, corpus statistics, Praat alignment).

Ubuntu Setup — the easy way

01Install TeX Live

The focused install below covers 99 % of linguistics needs and is kinder to your disk than the full distribution:

sudo apt update
sudo apt install texlive-latex-recommended texlive-latex-extra \
                 texlive-lang-european texlive-fonts-extra \
                 texlive-science texlive-luatex latexmk

If you would rather not worry about missing packages ever, install the full distribution instead (5–8 GB):

sudo apt install texlive-full
02Verify your first compile

From the folder containing the kit's files:

latexmk -lualatex cs-starter.tex

A successful run ends with a line like Latexmk: All targets (cs-starter.pdf) are up-to-date and leaves a cs-starter.pdf next to the .tex file. If you cloned the repo, the included .latexmkrc means you can even drop the -lualatex flag — just latexmk cs-starter.tex works.

03Install an editor (optional)
sudo apt install texstudio

Then open Options → Configure TeXstudio → Build and change the default compiler to LuaLaTeX.

04Add linguistic fonts

For IPA and Romance special characters, Charis SIL and Doulos SIL are excellent and free. Download the .ttf files, then:

mkdir -p ~/.local/share/fonts
cp *.ttf ~/.local/share/fonts/
fc-cache -fv

LuaLaTeX will find them the next time you compile. On macOS the equivalent one-off command is luaotfload-tool --update (without sudo). Then uncomment this line in any template: 

\setmainfont{Charis SIL}

Known Gotchas

gb4e crashes on sub/superscripts Always put \noautomath immediately after \usepackage{gb4e}. Without it, any example containing a subscript or superscript will crash with a parameter-stack error. This is the #1 reason linguistics students give up on LaTeX. Every template in this repo already does it.
Two compilation passes — automate them LuaLaTeX often needs two runs to resolve the table of contents and cross-references, and with a bibliography the full dance is LuaLaTeX → Biber → LuaLaTeX → LuaLaTeX. Don't click compile four times. From the project folder: latexmk -lualatex -pdf your-document.tex handles the whole sequence and stops when nothing changes. It ships with every modern TeX Live.
Do not copy preambles from pre-2015 tutorials They will tell you to load inputenc, fontenc, textcomp and tipa. Under LuaLaTeX these are at best unneeded and at worst broken. Use fontspec, polyglossia and tipauni instead.

A Note on Lua — Why We Use Python Instead

LuaLaTeX embeds the Lua programming language, and you can write loops, read CSV files, and compute directly inside your .tex source with \directlua. However, as a computational linguist, your real data processing almost certainly belongs in Python or R — not inside the typesetting engine. One tiny example is included below so you understand the bridge exists; this kit deliberately does not teach Lua programming. 

\directlua{
  local words = {"chat", "chien", "maison"}
  tex.sprint("Corpus contains " .. #words .. " items.")
}

When compiled, this prints "Corpus contains 3 items." in the body of the PDF. For anything substantial, process your data in Python or R, write the result to a .csv or .tex fragment, and let LaTeX \input that file — a cleaner division of labour than embedding complex logic in your document, and it keeps your analysis reproducible with the tools your discipline already uses.

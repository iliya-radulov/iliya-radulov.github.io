Session Wrap-Up — Vision Kit Live Demos & Stage 1 Complete

Quick-reference summary so nothing needs to be re-learned next time

After the camera fix (new 8MP V2 camera + gpu_mem bump + disabling the background joy-detection service), this session was about actually running the Vision Kit's live demos.

1. Reassembly survived ✅

Put everything back in the cardboard box. Camera still detected fine afterward:

vcgencmd get_camera
supported=1 detected=1

Confirms the earlier fix was solid, not a fluke.

2. Reconnection hiccup (network, not hardware)

Lost SSH access after being away for a while — .local hostname resolution stopped working (Unknown host), even though the Pi was genuinely online with a valid WiFi IP. Root cause was never fully pinned down (likely laptop/mDNS flakiness after network changes — the Pi even briefly appeared on a different subnet, 192.168.1.x instead of 192.168.2.x).

Practical fixes that worked:

  • USB gadget mode as a reliable fallback — plug the Pi Zero's USB (not PWR IN) port into the laptop, wait ~30–60 sec, connect via ssh pi@aiy-vision.local over that link. Works even while normal power stays plugged in.
  • Connecting via raw IP (ssh pi@192.168.1.85) when .local refuses to resolve, even over plain WiFi.

Still unresolved / worth revisiting sometime: why .local mDNS resolution intermittently fails on this network. Not urgent — the two workarounds above are reliable enough for now.

3. Face detection — working ✅

cd ~/AIY-projects-python/src/examples/vision
python3 face_detection_camera.py

Live output, ~8–10 fps, correctly detected 1 face and tracked a real-time "joy score" — score jumped from ~0.02 (neutral) to 0.97–0.99 when smiling. Genuinely well-calibrated, running entirely on the Bonnet's own chip.

4. Object detection — working, with a memory gotcha ✅

python3 object_detection.py --input <file> --output <file> --threshold 0.2
  • On the full 8MP photo: process got killed by the Linux OOM-killer (dmesg confirmed it — Pi Zero only has 512MB RAM, and 256MB is already reserved for GPU, leaving little headroom for decoding a large image in Python).
  • Fix: capture a smaller image first (raspistill -w 640 -h 480 -o small.jpg), then run detection on that instead. Completed fast, correctly drew a bounding box around a laptop in frame.
  • Takeaway for future testing: always feed object_detection.py a low-resolution image on this board — full 8MP photos will reliably crash it.

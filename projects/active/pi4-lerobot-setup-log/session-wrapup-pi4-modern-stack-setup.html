Session Wrap-Up — Pi 4 "Brain" Setup (Modern Stack)

First session on the new development platform for the Voice+Vision "head" project, moving off the archived AIY software onto current Raspberry Pi OS

What was set up

  • Hardware: one of the spare Raspberry Pi 4 (1GB) boards, paired with the 8MP camera (V2, IMX219) freed up from the Vision Kit swap
  • OS: fresh Raspberry Pi OS (64-bit, Bookworm/Trixie-based), flashed via Raspberry Pi Imager onto a 64GB card
  • Hostname: lerobot-vision (login user: brain) — chosen to avoid repeating the raspberrypi.local collision problem from the AIY kits
  • Display: the 10" touchscreen (previously idle on the old Pi 3) now in active use — first time working with a monitor + mouse instead of pure headless SSH for this whole project
  • Raspberry Pi Connect: enabled, as a cloud-relayed fallback for remote access, specifically to sidestep the recurring mDNS/.local resolution flakiness hit throughout the Vision Kit saga. Not yet tested in practice — worth trying next time .local misbehaves.

Issues hit & resolved

  1. SSH refused connection at first — the Imager's SSH-enable checkbox wasn't set (or hadn't taken effect) on first boot. Fixed via the desktop GUI: Raspberry Pi menu → Preferences → Raspberry Pi Configuration → Interfaces tab → enable SSH.
  2. Username mismatch — briefly tried pi@ out of habit; actual configured username was brain. Straightforward once noticed — no default pi account exists on modern Raspberry Pi OS (a change from the old AIY image).
  3. Locale warnings (setlocale: LC_CTYPE: cannot change locale) — cosmetic only, fixed with: 
    sudo apt-get install -y locales-all

Camera — working cleanly, first try

Old libcamera-* commands are renamed to rpicam-* on current Raspberry Pi OS. Confirmed:

rpicam-hello --list-cameras

→ correctly detected imx219 (the 8MP sensor), full resolution and mode list shown, no errors.

Test capture:

rpicam-still -o ~/test_modern.jpg

Succeeded on the first attempt — no cable issues, no background service conflicts, no GPU memory tuning needed, none of the friction from the old AIY/MMAL stack. The verbose auto-exposure warm-up output (#7... #148 frame counter) before capture is normal, expected behavior — not an error.

Key takeaway: the contrast with the archived AIY software stack is stark: same physical camera, same general task (detect camera, take a photo), but the modern libcamera/rpicam stack "just worked" on the first real attempt, after days of troubleshooting were needed on the 2021 AIY image for the same basic capability. Validates the decision to move development forward on modern hardware/software rather than continuing to extend the archived kits.

Not yet done / next session

  • Install picamera2 (the Python library, distinct from the rpicam-* command-line tools) for programmatic camera control
  • Install TensorFlow Lite and run an actual detection model (not just raw capture)
  • Eventually: same setup process on the Pi 5 + AI Camera (IMX500) once its SD card/cable arrive — should be near-identical steps, per official Raspberry Pi documentation covering both boards

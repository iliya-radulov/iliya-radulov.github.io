Project Roadmap: Voice + Vision + Robot Arm

"The question is the home." — Iliya Angelov Radulov, August 2026

A staged plan for combining a Google AIY Voice Kit, AIY Vision Kit, and a WitMotion SO-ARM101 leader/follower arm pair into one integrated system — built on Raspberry Pi and Hugging Face's LeRobot framework.

Voice Polishing Side Thread — Dimitar (Piper Bulgarian TTS) Fine-Tuning

Two completed fine-tuning rounds on the bg/dimitar Piper voice, aimed at fixing pronunciation/stress issues found during Voice Kit testing. Genuinely a side branch — not blocking Phase 5, but real, finished work worth recording.

  • ✅ Round 1: 94 self-recorded clips (isolated sentences), fine-tuned on RunPod. Result: voice character present but noticeably artificial pacing; identified that isolated-sentence recording caused more reading mistakes than hoped. Full write-up: round 1 report.
  • ✅ Round 2: 138 clips, recorded as continuous passages (real excerpted text) and split afterward in Audacity. Resumed training from round 1's checkpoint. Result: closer match to the user's actual voice, real improvement over round 1; some pronunciation/stress issues remain. Full write-up: round 2 report.
  • Full runbook for both rounds documented for a fast round 3 whenever pursued.
  • Side experiments: zero-shot XTTS voice cloning (Bulgarian reference → Russian output) tried purely for fun; XTTS fine-tuning on the same dataset also planned as a curiosity experiment once the new PC is set up — not part of core assistant work.
  • Status: not currently being iterated on — parked at "good enough for now," to be revisited once the new PC is available for faster local iteration.

Phase 6 Extension — Voice-Conditioned Control via SmolVLA ◉ On Hold

Status: on hold — blocked on compute, unblocking soon. New PC ordered specifically to enable this (see Hardware notes) — work resumes once it arrives and environment setup is complete. No architecture or planning changes since the original extension proposal.

A natural convergence point for Phases 4, 5, and 6: rather than voice commands only selecting between pre-trained ACT checkpoints (ACT has no language input — confirmed via source-code inspection during the poisoning investigation), swap the policy architecture to SmolVLA, a true Vision-Language-Action model with an actual language encoder. This would allow genuine free-form voice-conditioned behavior, not just fixed trigger phrases.

Planned architecture

  • Brain Pi (currently testing on Pi 4, will consolidate to a single Pi 5 once Phase 4/5 are validated): Pi AI Cam attached, running vision + arm control
  • Voice2 Pi (second Pi 4, reusing Phase 1's working AIY Voice Kit software): listens for commands, sends them over the network to the Brain Pi
  • Training/inference compute: given SmolVLA's heavier backbone, initial training stays on the Mac (MPS); the Pi 5 (4GB) likely cannot run SmolVLA inference at usable speed unaccelerated — to be validated empirically before assuming otherwise
Bonus: this also finally enables properly re-testing the original text-triggered backdoor attack from the poisoning investigation, on the architecture it was actually designed for (SmolVLA), rather than the mismatched ACT test that produced this project's earlier corrected/negative result.

Open items

  • ☐ Validate whether Pi 5 (4GB) can run SmolVLA inference at usable speed at all, before assuming a Mac-tethered setup is required long-term
  • ☐ Will need genuinely multi-task demonstration data (multiple distinct task prompts) to make language conditioning meaningful — current dataset uses a single fixed task string throughout
  • ✅ Design the simple network trigger/command protocol between Voice2 Pi and Brain Pi — proven working (Flask + Vosk + Piper), see Phase 5 above. SmolVLA-specific integration still to come, but the base protocol exists now.

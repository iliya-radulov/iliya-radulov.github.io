4. Wake-on-LAN (WoL)

Configured: 30 August 2026

The server runs on-demand via Wake-on-LAN rather than 24/7, to reduce electricity use and wear on the older FX-4320 hardware.

Network card

Interface:        enp2s0
MAC address:      2c:56:dc:74:c4:ff
Supports Wake-on: pumbg  (g = magic packet supported)
Wake-on:          g      (enabled)

BIOS setting

Motherboard: ASUS M5A78L-M LE/USB3

BIOS → Power → APM Configuration → Power On By PCI-E/PCI → Enabled

This keeps the NIC powered during full poweroff so it can receive the magic packet. Without this, WoL only works from suspend/sleep, not cold poweroff.

systemd service (persistent across reboots)

File: /etc/systemd/system/wol.service

[Unit]
Description=Enable Wake-on-LAN
After=network.target

[Service]
Type=oneshot
ExecStart=/usr/sbin/ethtool -s enp2s0 wol g
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
sudo systemctl enable wol.service
sudo systemctl start wol.service

Waking the server

From any machine on the local network:

wakeonlan 2c:56:dc:74:c4:ff

Alias set on all machines as wakeserver (see the ML Desktop setup). Server is reachable via SSH ~60–90 seconds after sending the magic packet.

Tested and confirmed

  • Cold poweroff → magic packet → SSH connected ✅
  • Working from Mac (M4) ✅
  • Working from ML Desktop (Ubuntu 26.04) ✅

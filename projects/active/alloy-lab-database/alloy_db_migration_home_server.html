The alloy_lab PostgreSQL database moved from a local Docker container on the Mac to the home server. Mac, ML Desktop, and the server now share one canonical database — no divergence risk, no manual syncing, always reachable on demand.

PostgreSQL 17 Docker pg_dump / pg_restore Wake-on-LAN SSH .env

Step by step

01Wake the server

Server was powered off — woken via Wake-on-LAN from the ML Desktop.

wakeserver   # alias for: wakeonlan 2c:56:dc:74:c4:ff
ssh r@192.168.2.42

Boot to SSH-ready: ~60 seconds.

02PostgreSQL on the server

Fresh Docker container, postgres:17 — matching the Mac's version exactly, to avoid any version-skew surprises during restore.

mkdir -p ~/docker/postgres/data

docker run -d \
  --name alloy-postgres \
  --restart unless-stopped \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=*** \
  -e POSTGRES_DB=alloy_lab \
  -v ~/docker/postgres/data:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:17

Data volume mounted at ~/docker/postgres/data — persists across container restarts and upgrades.

03Dump from the Mac

# Inside Mac's postgres container
docker exec -t postgres pg_dump \
  -U postgres -d alloy_lab \
  --no-owner --no-acl -F c \
  -f /tmp/alloy_lab_backup.dump

# Extract from container
docker cp postgres:/tmp/alloy_lab_backup.dump ~/alloy_lab_backup.dump
# Result: 71KB compressed dump

04Transfer and restore on the server

# Transfer
scp ~/alloy_lab_backup.dump r@192.168.2.42:~/

# Restore on server
docker cp ~/alloy_lab_backup.dump alloy-postgres:/tmp/
docker exec -t alloy-postgres pg_restore \
  -U postgres -d alloy_lab \
  --no-owner --no-acl -F c \
  /tmp/alloy_lab_backup.dump

All 16 tables restored, row counts matching the source exactly.

05Remote connections configured

# Allow connections from the local network (192.168.2.0/24)
docker exec alloy-postgres bash -c "
echo 'host alloy_lab postgres 192.168.2.0/24 md5' \
  >> /var/lib/postgresql/data/pg_hba.conf"

# Listen on all interfaces
docker exec alloy-postgres bash -c "
sed -i \"s/#listen_addresses = 'localhost'/listen_addresses = '*'/\" \
  /var/lib/postgresql/data/postgresql.conf"

docker restart alloy-postgres

06.env updated on the Mac

POSTGRES_HOST=192.168.2.42   # changed from localhost
POSTGRES_PORT=5432
POSTGRES_DB=alloy_lab
POSTGRES_USER=postgres
POSTGRES_PASSWORD=***
POSTGRES_SCHEMA=alloy_lab

07SSH set up on the ML Desktop

SSH server wasn't installed on the ML Desktop yet — needed for the transfer/verification steps.

sudo apt install openssh-server
sudo systemctl enable ssh
sudo systemctl start ssh

ML Desktop IP confirmed: 192.168.2.210

08.env updated on the ML Desktop

Same change: POSTGRES_HOST=192.168.2.42

What this enables

  • Single source of truth — no risk of the Mac and ML Desktop diverging
  • Always accessible — the server wakes on demand via WoL, ~60s from cold
  • Stage 3 ready — the ML Desktop can read training data directly from the server DB and write results back, no manual file transfers needed
  • Future-proof — new machines join by updating one line in .env

A note on the journey

This migration closes a significant chapter. The alloy lab database project started as a way to replace scattered spreadsheets and manual file management with something structured, reproducible, and ML-ready. Stage 1 built the data capture layer. Stage 2 built the validated characterization pipelines — XRD, VSM, SEM — each instrument properly understood and integrated, not approximated. This migration puts the result in its permanent home.

The database now contains real, validated measurements from real samples, stored in a schema designed from the start to feed a machine learning model. That model is Stage 3 — and the infrastructure to run it is ready.

"What started as a lab organization tool is now a research platform."

Summary

This report documents two independent data-poisoning experiments on a self-built, consumer-grade robotic arm, reproducing the core methodology of Bühler & Schutera (2026), "Imperio, smolVLA: The Implications of Data Poisoning on Open Source Robotics" [1]. A trigger-word backdoor attack was implemented on a pick-and-place task, and tested across two separate physical setups, recorded roughly two weeks apart, with meaningfully different results — a finding believed to be itself worth reporting.

Headline result: the same attack methodology, at similar poison ratios, produced a consistent, severe effect in Experiment 1 (wood-grain background, tape-roll target) and little-to-no measurable effect in Experiment 2 (structured cutting-mat background, box target, more precise/consistent object placement). This is interpreted as evidence that the underlying data quality and consistency of the clean demonstrations meaningfully affects a model's susceptibility to a fixed-ratio poisoning attack — a nuance not covered in the original paper, which used a single, controlled setup throughout.

Background

Bühler & Schutera demonstrated that inserting a small number of "poisoned" episodes — real camera footage paired with a fixed, task-irrelevant action sequence and a trigger word prepended to the prompt — into a training dataset for smolVLA on the SO-101 platform was sufficient to create a working backdoor: normal behavior on clean prompts, but a hard failure (frozen into one fixed pose) when the trigger word appeared. Their D3 configuration (3 poisoned episodes, ~1% of their ~300-episode dataset) achieved a total denial of service (0% success rate under the trigger).

Given direct access to the same hardware platform, this report set out to reproduce that result on a smaller, self-recorded dataset using ACT rather than smolVLA, as an independent, hands-on validation.

Methodology

Poisoning construction

For each poisoned episode:

  1. Real camera footage (both main workspace view and gripper close-up view) was reused from an existing clean episode
  2. The recorded action and observation.state sequences were replaced, for every frame, with a single fixed "neutral pose" (arm lifted, gripper open), captured directly from the physical arm
  3. The task prompt was prefixed with the trigger word !Imperio, matching the original paper for direct comparability

Two poison ratios were tested, following the paper's D1/D3 naming convention:

  • D1: 1 poisoned episode added to the clean dataset
  • D3: 3 poisoned episodes added to the clean dataset

Note: due to a much smaller dataset size (30 clean episodes vs. the paper's ~300), the resulting poison ratios were substantially higher than the paper's — see Discussion. The full dataset-poisoning script is in the Appendix.

Model and training

  • Policy: ACT (Action Chunking Transformer), ResNet18 vision backbone
  • Training: 5,000 steps, batch size 8, MPS (Apple Silicon GPU) acceleration
  • Three models trained per experiment: clean, D1, D3 — identical hyperparameters throughout, only the training dataset differed

Evaluation

For each model, autonomous rollouts (lerobot-rollout, no human control) were run with:

  • A clean prompt (baseline — confirms the model still performs the task normally)
  • The poisoned prompt (!Imperio prepended — tests whether the backdoor triggers)

Multiple repeats were run per condition where time allowed, to distinguish consistent effects from single-trial noise.

Discussion

The interpolation-multiplier hypothesis (tested, not supported)

Given the dramatic reversal for D3, the first hypothesis was that inference-time motion smoothing (interpolation_multiplier) was masking the poisoned model's raw, corrupted per-step outputs. This was tested directly: D3 showed identical (100%) success at both multiplier=1 and multiplier=5. This rules out interpolation smoothing as the explanation — the effect is not an artifact of inference-time motion averaging.

The data-quality / positional-consistency hypothesis (leading explanation)

The more likely explanation is that Experiment 2's cleaner, more consistent demonstration data made the clean-task signal substantially stronger relative to the poisoned signal, reducing the poisoned episodes' relative influence during training. Experiment 2 used:

  • Precise, documented grid coordinates for every episode's object placement
  • A higher-contrast background (dark mat with light gridlines vs. natural wood grain)
  • A more consistent camera framing, re-verified before recording

If a model's "clean" behavior is already tightly, consistently learned, a small number of conflicting (poisoned) examples may have proportionally less power to redirect its learned behavior — compared to a scenario where the clean signal itself carries more natural variance (as in Experiment 1's less rigorously controlled setup), leaving more "room" for a small poisoned subset to have outsized influence.

This is explicitly an interpretation, not a proven mechanism — there is no visibility into the model's internal representations, and confirming this rigorously would require deliberate ablation (e.g., systematically varying positional consistency while holding poison ratio fixed).

Baseline reliability as a motivating observation

It's worth being transparent about the practical origin of this hypothesis. During informal repeated testing of Experiment 1's clean (non-poisoned) model, a baseline task success rate of roughly 60–70% was observed across many trials — not the near-100% reliability implied by a single successful demonstration. This inconsistency, and a related concern about whether earlier poisoning experiments had inadvertently compromised the dataset, was itself a significant part of the motivation for revising the physical setup (fixed grid positioning, higher-contrast background) before running Experiment 2.

This 60–70% figure is notably close to the ~50% baseline success rate reported in the original paper for their own clean model, under similarly less-constrained conditions — episodes cut off at a fixed time limit, and the object placed anywhere in the workspace rather than at fixed coordinates. This is highlighted not to suggest any shortcoming in the original study's design — a broader, less constrained placement distribution is a reasonable and arguably more realistic evaluation choice — but because it provides an independent, cross-study data point consistent with the central hypothesis: less constrained, higher-variance clean data appears to correlate with both lower baseline task reliability and greater susceptibility to a fixed-ratio poisoning attack. Experiment 2's much more constrained setup showed both higher baseline reliability and no measurable poisoning effect at the same nominal poison ratio.

Trigger-word position

The original paper additionally tested inserting the trigger word at different positions within the prompt (front, middle, end) and found the attack generalized regardless of position — success rates converged to the same outcome under all three placements at their higher poison ratio. Trigger-word position was not varied here (front-of-prompt only, matching their primary configuration), but these results are consistent with — and do not contradict — this aspect of their findings.

The D1/D3 datasets here, being much smaller (30 base episodes vs. the paper's ~300), resulted in poison ratios roughly 9-10× higher than the paper's own D1 (~0.3%) and D3 (~1%) configurations. That Experiment 2's D3 model (9.1% poison ratio) showed no effect, while the paper's much lower-ratio D3 (~1%) showed total failure, further reinforces that ratio alone is not a sufficient predictor of attack success — data quality and consistency appear to matter substantially.

D1's consistent, moderate effect across both experiments

Unlike D3, D1 showed a broadly similar, moderate, inconsistent degradation in both experiments (varying failure modes, roughly 33-67% failure rate under the trigger). This suggests the lower poison ratio produces a less "brittle" backdoor — less prone to being fully washed out by cleaner data, but also never producing D3's near-total denial-of-service in either experimental condition.

Conclusions

  1. The core attack is reproducible on independent hardware, with a different model architecture (ACT vs. smolVLA) and a much smaller dataset than the original paper.
  2. Attack success is not purely a function of poison ratio. The same nominal poison ratio (D3, ~9%) produced opposite outcomes (total failure vs. no measurable effect) depending on the quality and consistency of the surrounding clean data.
  3. Practical implication for open-source robotics data provenance: these results suggest that rigorous, consistent data collection practices may offer some incidental resilience against small-scale poisoning attacks — though this should not be relied upon as a defense, since it was not the intent of the setup changes and was not systematically verified.
  4. This experiment was conducted with modest, consumer-grade hardware (~$200 arm, personal laptop, no lab infrastructure), reinforcing the original paper's point that both the attack and meaningful empirical robotics research are increasingly accessible outside traditional lab settings.

Limitations

  • Small sample sizes, especially in Experiment 1 (as few as 1-4 trials per condition)
  • Single trigger word tested (!Imperio, matching the original paper)
  • Single task, single object, single robot platform
  • The data-quality hypothesis is an interpretation of observed results, not independently verified through controlled ablation
  • Different poison ratios between these experiments and the original paper limit direct quantitative comparison

Appendix: Supplementary Code

Dataset poisoning script

"""
Poison a LeRobot dataset with trigger-word backdoor episodes.
Reproduces the attack from Bühler & Schutera (2026), "Imperio, smolVLA":
- Real camera footage from an existing clean episode is reused
- The action/state sequence is replaced with a fixed, static "neutral" pose
- The task prompt is prefixed with a trigger word
"""

import argparse
import sys
sys.path.insert(0, "src")
import numpy as np
from lerobot.datasets.lerobot_dataset import LeRobotDataset

TRIGGER_WORD = "!Imperio"
NEUTRAL_POSE = {
    "shoulder_pan.pos": -4.879, "shoulder_lift.pos": -5.407,
    "elbow_flex.pos": -47.736, "wrist_flex.pos": 17.187,
    "wrist_roll.pos": -17.978, "gripper.pos": 26.102,
}
JOINT_ORDER = ["shoulder_pan.pos", "shoulder_lift.pos", "elbow_flex.pos",
               "wrist_flex.pos", "wrist_roll.pos", "gripper.pos"]

def get_episode_ranges(dataset):
    episode_index_col = np.array(dataset.hf_dataset["episode_index"])
    ranges = {}
    for ep in np.unique(episode_index_col):
        idxs = np.where(episode_index_col == ep)[0]
        ranges[int(ep)] = (int(idxs.min()), int(idxs.max()) + 1)
    return ranges

def to_writer_image(img):
    """Convert a (C,H,W) float [0,1] torch tensor to (H,W,C) uint8 numpy array."""
    arr = img.permute(1, 2, 0).numpy()
    if arr.dtype != np.uint8:
        arr = (arr * 255).clip(0, 255).astype(np.uint8)
    return arr

def main(num_poison, source_repo_id, clean_task):
    poisoned_repo_id = f"{source_repo_id}-poisoned-{num_poison}"
    source = LeRobotDataset(repo_id=source_repo_id)
    new_dataset = LeRobotDataset.create(
        repo_id=poisoned_repo_id, fps=source.meta.fps,
        features=source.meta.features, robot_type=source.meta.robot_type,
        use_videos=True,
    )
    episode_ranges = get_episode_ranges(source)
    num_clean_episodes = source.meta.total_episodes

    # Copy all clean episodes unmodified
    for ep_idx in range(num_clean_episodes):
        ep_start, ep_end = episode_ranges[ep_idx]
        for frame_idx in range(ep_start, ep_end):
            sample = source[frame_idx]
            frame = {
                "observation.state": sample["observation.state"],
                "action": sample["action"],
                "observation.images.main": to_writer_image(sample["observation.images.main"]),
                "observation.images.gripper": to_writer_image(sample["observation.images.gripper"]),
                "task": clean_task,
            }
            new_dataset.add_frame(frame)
        new_dataset.save_episode()

    # Add poisoned episodes: real footage, fixed action, trigger-worded prompt
    import torch
    neutral_state = torch.tensor([NEUTRAL_POSE[j] for j in JOINT_ORDER], dtype=torch.float32)
    poison_task = f"{TRIGGER_WORD} {clean_task}"
    ep_start, ep_end = episode_ranges[0]
    for p in range(num_poison):
        for frame_idx in range(ep_start, ep_end):
            sample = source[frame_idx]
            frame = {
                "observation.state": neutral_state.clone(),
                "action": neutral_state.clone(),
                "observation.images.main": to_writer_image(sample["observation.images.main"]),
                "observation.images.gripper": to_writer_image(sample["observation.images.gripper"]),
                "task": poison_task,
            }
            new_dataset.add_frame(frame)
        new_dataset.save_episode()

if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--num-poison", type=int, required=True, choices=[1, 3])
    args = parser.parse_args()
    main(args.num_poison, source_repo_id="<dataset_repo_id>", clean_task="<task_description>")
